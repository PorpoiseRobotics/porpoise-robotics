# Porpoise Robotics git guides

These guides teach git and GitHub from absolute zero. They assume you have never opened a
terminal, have never made a commit, and are not sure what any of these words mean. That is
completely fine — everyone starts there.

**Read them in this order.**

### [1. Installing git and setting it up](01-install-git.md)
Install git on Windows, macOS, or Linux. Tell git who you are. Create a GitHub account and
connect it. Also covers **GitHub Desktop**, a point-and-click app that does most of this
without a terminal — a completely legitimate way to work.

*Do this once per computer. After that you never think about it again.*

### [2. The everyday workflow](02-everyday-workflow.md)
The loop you will repeat forever: pull, branch, edit, add, commit, push, open a pull request,
merge. Every command is shown with the output you should actually see, in both terminal and
GitHub Desktop.

*This is the one to keep open in a tab while you work.*

### [3. Plain-English glossary](03-glossary.md)
What "repo", "clone", "branch", "commit", "push", "remote", "origin", "HEAD", "PR", "merge",
and "conflict" actually mean. No jargon explained using other jargon.

*Look things up here whenever a word stops making sense.*

### [4. When things go wrong](04-when-things-go-wrong.md)
The most useful guide here. What to do when you commit to the wrong branch, hit a merge
conflict, want to undo something, push something you shouldn't have, or are simply afraid of
breaking things.

*Read it once before you need it, so you know it exists when you do.*

### [5. Why empty folders have a `.gitkeep` file](05-gitkeep-and-empty-folders.md)
Short explanation of the odd empty files scattered through this repository.

*Read when you notice them and wonder what they are.*

---

## The one thing to remember

Git is designed so that committed work is extremely hard to lose. Almost every mistake you can
make is reversible, usually in one command. You are not going to break the project by trying
something. Experiment freely.
